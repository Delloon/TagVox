# Discord-бот на Rust (serenity + songbird)

Консольный Discord-бот, написанный на Rust. Реагирует на упоминание набором
настраиваемых фраз, по голосовым командам подключается к голосовому каналу
и воспроизводит локальные аудиофайлы с поддержкой паузы/возобновления и
кнопок управления в чате.

## Возможности

- **Реакции на упоминание.** При упоминании бота его сообщение сравнивается
  с триггерами из `phrases.json` нечётким сравнением (учитываются похожие
  формулировки, а не только точные совпадения), и в ответ отправляется одна
  из заданных фраз.
- **Голосовые команды.** Если фраза похожа на одну из `voice_commands`, бот
  подключается к голосовому каналу, где находится автор сообщения, и
  воспроизводит привязанный к этой фразе локальный аудиофайл.
- **Пауза и возобновление.** Позиция трека сохраняется автоматически (через
  `songbird`), пока трек не остановлен явно.
- **Кнопки управления.** Под сообщениями о воспроизведении появляются
  интерактивные кнопки «Пауза» / «Продолжить» / «Стоп» — они работают в том
  же канале, где была вызвана команда.
- **Неограниченное количество реакций и команд** — всё задаётся в JSON,
  количество записей не ограничено.
- **Автоматическая настройка при первом запуске.** Токен запрашивается один
  раз через консоль и сохраняется локально; настройки бота создаются
  автоматически со значениями по умолчанию.
- **Автокопирование ресурсов при сборке.** `phrases.json` и папка `sounds/`
  копируются в папку с исполняемым файлом автоматически при сборке.

## Требования

- Rust (стабильная версия, 1.83 или новее) — https://rustup.rs
- CMake — нужен для сборки библиотеки Opus (аудиокодек, который использует
  Discord)
- На Windows — компилятор C/C++ (Visual Studio Build Tools с компонентом
  «Desktop development with C++», либо полная Visual Studio)
- `ffmpeg` — используется `songbird` для декодирования аудио
- Discord-приложение с включённым **Message Content Intent**

## Установка зависимостей сборки

### CMake

CMake необходим, так как крейт, отвечающий за поддержку кодека Opus,
собирает библиотеку Opus из C-исходников.

1. Скачать установщик с https://cmake.org/download/ и установить.
2. При установке отметить опцию добавления CMake в PATH (для всех
   пользователей или для текущего пользователя).
3. Открыть новую сессию терминала (важно — старая сессия не увидит
   обновлённый PATH) и проверить: `cmake --version`.

Если сборка завершается ошибкой вида
`Compatibility with CMake < 3.5 has been removed from CMake` — значит,
установлена версия CMake 4.x, а исходники Opus указывают устаревшую
минимальную версию политики. Обход:

```powershell
# PowerShell (действует только в текущей сессии терминала)
$env:CMAKE_POLICY_VERSION_MINIMUM="3.5"
```

```bat
:: CMD
set CMAKE_POLICY_VERSION_MINIMUM=3.5
```

Чтобы не задавать переменную каждый раз, её можно добавить в системные
переменные окружения постоянно (Панель управления → Система → Дополнительные
параметры системы → Переменные среды).

### ffmpeg

- Ubuntu/Debian: `sudo apt install ffmpeg`
- macOS: `brew install ffmpeg`
- Windows: скачать сборку с https://ffmpeg.org и добавить путь к `ffmpeg.exe`
  в PATH

### C++ Build Tools (только Windows)

Если сборка завершается ошибкой об отсутствующем компиляторе, необходимо
установить компонент «Desktop development with C++» через Visual Studio
Installer (Visual Studio Build Tools или полная Visual Studio подходят
одинаково).

## Сборка

```bash
git clone <адрес репозитория>
cd discord-bot
cargo build --release
```

При сборке (см. `build.rs`) `phrases.json` и папка `sounds/` автоматически
копируются в `target/release/` (или `target/debug/`), если их там ещё нет.
Уже существующие в целевой папке файлы не перезаписываются, поэтому
локальные правки, внесённые прямо в `target/release/`, сохраняются между
пересборками.

## Настройка Discord-приложения

1. Создать приложение на https://discord.com/developers/applications.
2. В разделе Bot → Privileged Gateway Intents включить **Message Content
   Intent**.
3. Через OAuth2 → URL Generator сформировать ссылку приглашения со scope
   `bot` и правами: View Channels, Send Messages, Read Message History,
   Connect, Speak.
4. Перейти по ссылке и выбрать сервер для добавления бота.

## Файлы настроек

### `config.json` (создаётся автоматически при первом запуске)

```json
{
  "command_prefix": "!",
  "similarity_threshold": 0.78,
  "require_mention_for_reactions": true,
  "sounds_dir": "sounds"
}
```

- `command_prefix` — префикс управляющих команд (`!pause`, `!resume` и т.д.).
- `similarity_threshold` — порог похожести фразы на триггер (0.0–1.0). При
  необходимости распознавать более разнообразные формулировки значение
  снижается; для более строгого совпадения — повышается.
- `require_mention_for_reactions` — если `false`, реакции и голосовые
  команды срабатывают без упоминания бота, на любое сообщение.
- `sounds_dir` — папка по умолчанию для звуковых файлов, если в
  `phrases.json` в поле `file` указано только имя файла без пути.

### `token.json` (создаётся автоматически при первом запуске)

При первом запуске исполняемого файла в консоли запрашивается токен бота
(ввод скрыт). После ввода токен сохраняется в `token.json` рядом с
исполняемым файлом; при последующих запусках запрос не повторяется.

```json
{ "token": "токен_бота" }
```

Этот файл содержит секретные данные и не должен публиковаться или
попадать в систему контроля версий (см. `.gitignore`).

### `phrases.json` (редактируется вручную, пример входит в репозиторий)

```json
{
  "text_reactions": [
    {
      "id": "greeting",
      "triggers": ["привет", "хай"],
      "responses": ["Привет!", "Здорово!"]
    }
  ],
  "voice_commands": [
    {
      "id": "sad_song",
      "triggers": ["включи грустную песню"],
      "file": "sad_song.mp3"
    }
  ],
  "unknown_response": ["Не понял, что имеется в виду."]
}
```

Поле `file` может содержать либо имя файла (тогда путь берётся из
`sounds_dir`), либо полный/относительный путь со слэшами. Количество
записей в `text_reactions` и `voice_commands` не ограничено.

## Запуск

```bash
cargo run --release
```

либо напрямую скомпилированный файл:

```bash
./target/release/discord-bot
```

## Команды в Discord

Управляющие команды работают с указанным префиксом (по умолчанию `!`) и не
требуют упоминания бота:

| Команда              | Действие                                             |
|----------------------|-------------------------------------------------------|
| `!join`               | подключиться к голосовому каналу автора сообщения      |
| `!leave`               | отключиться от голосового канала                       |
| `!pause`               | поставить текущий трек на паузу (позиция сохраняется) |
| `!resume` / `!continue` | продолжить с сохранённой позиции                       |
| `!stop`                | остановить и сбросить позицию                          |
| `!ping`                | показать текущую задержку соединения с Discord         |

Реакции на упоминание и голосовые команды задаются в `phrases.json` и
срабатывают, когда бот упомянут в сообщении (если в `config.json` не
отключено требование упоминания).

## Кнопки управления

Когда бот запускает или возобновляет трек, под сообщением появляются
кнопки «⏸ Пауза», «▶ Продолжить», «⏹ Стоп». Они действуют в том же
канале, где была вызвана команда; ответ на нажатие приходит эфемерным
сообщением, видимым только нажавшему.

## Дебаг и диагностика

- Каждые 30 секунд в консоль выводится задержка соединения (пинг) по
  каждому шарду.
- При каждой попытке подключения к голосовому каналу в консоль выводится
  результат — успех или причина отказа с расшифровкой типичных причин
  (отсутствие прав, блокировка UDP-трафика антивирусом/файрволом/VPN,
  Stage-канал и т.д.).
- Для более подробных логов используется переменная окружения `RUST_LOG`:

  ```powershell
  $env:RUST_LOG="debug"; cargo run --release
  ```

## Структура проекта

```
discord-bot/
├── Cargo.toml
├── build.rs              # копирует phrases.json и sounds/ в target/<profile> при сборке
├── phrases.json           # реакции, голосовые команды, фраза-заглушка
├── sounds/                 # локальные аудиофайлы для голосовых команд
├── .gitignore
└── src/
    ├── main.rs
    ├── config.rs           # загрузка/создание config.json
    ├── token_store.rs      # запрос и хранение токена
    ├── phrases.rs          # загрузка phrases.json и нечёткое сравнение фраз
    ├── state.rs            # общее состояние приложения
    └── handler.rs          # обработка сообщений, кнопки, воспроизведение
```

Файлы `config.json` и `token.json` в структуру не включены — они создаются
автоматически при первом запуске и не должны попадать в репозиторий.
