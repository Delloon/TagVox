# API-контракт веб-панели TagVox

Фронтенд в этой папке ничего не знает о реализации бэкенда — он работает
против REST API, описанного ниже. Пока бэкенда на Axum нет, все запросы
будут падать с ошибкой сети, и интерфейс покажет соответствующее состояние
(это ожидаемо и корректно обрабатывается).

Все запросы — с `credentials: "include"` (сессионная кука). Тело запросов
и ответов — JSON, кроме загрузки файлов (`multipart/form-data`).

## Аутентификация

Панель поддерживает два режима входа, выбранных один раз при первом запуске
(вопрос в консоли) и сохранённых в `panel.toml` → `auth_mode` (`"discord"`
или `"password"`).

| Метод | Путь                          | Описание                                                                 |
|-------|-------------------------------|---------------------------------------------------------------------------|
| GET   | `/api/auth/mode`              | Публичный, без сессии. `{ "mode": "discord" \| "password" }` — фронтенд решает, какой экран логина показать |
| GET   | `/api/auth/discord/login`     | (режим `discord`) Редиректит (302) на `discord.com/api/oauth2/authorize`  |
| GET   | `/api/auth/discord/callback`  | (режим `discord`) Discord возвращает сюда с `?code=...&state=...`. Обменивает код на токен, проверяет допуск (таблица `admins`), создаёт сессию, ставит куку, редиректит на `/`. При ошибке — редирект на `/?login_error=...` |
| POST  | `/api/auth/password/login`    | (режим `password`) `{ "password": "..." }` → `204` + HttpOnly-кука, либо `401` при неверном пароле |
| POST  | `/api/auth/logout`            | `204`, удаляет сессию и куку (работает в обоих режимах)                   |

**Режим `discord`:** кнопка «Войти через Discord» на фронтенде — обычная
ссылка (`<a href="/api/auth/discord/login">`), а не fetch-запрос: браузер
должен реально перейти на страницу согласия Discord. Допуск — allow-list в
таблице `admins`; первый администратор добавляется автоматически, если его
Discord ID совпадает с `initial_admin_discord_id` в `panel.toml`.

**Режим `password`:** один общий пароль на панель, без allow-list. Пароль
задаётся один раз при первом запуске (вопрос в консоли, ввод скрыт) и
хранится в `panel.toml` только в виде хеша (Argon2) — сам пароль нигде не
сохраняется. Подходит, когда настраивать Discord OAuth-приложение и
redirect URI неудобно (например, панель открывается не с той же машины, где
запущен бот).

Любой запрос к `/api/*` кроме `/api/auth/*` без валидной сессии возвращает
`401`. Фронтенд при получении `401` показывает экран логина.

## Звуковые файлы (sounds/)

| Метод  | Путь                     | Тело / Ответ                                                                 |
|--------|----------------------------|-----------------------------------------------------------------------------------|
| GET    | `/api/sounds`              | `[ { "name": string, "size_bytes": number, "modified_at": string (ISO 8601) } ]` |
| POST   | `/api/sounds`               | `multipart/form-data`, поле `file`; ответ — `{ "name", "size_bytes" }`           |
| DELETE | `/api/sounds/{name}`        | `204`                                                                              |

Загрузка проверяет расширение файла (mp3/ogg/wav/flac, до 50 МБ) и защищает
от path traversal в имени файла — `name` из формы не используется буквально,
санитизируется до голого имени файла без слэшей и `..`.

Сами аудиофайлы (для предпрослушивания в браузере через `<audio>`) доступны
по пути `/sounds/{name}` — этот путь вне `/api`, но защищён той же сессией,
что и остальная панель (браузер сам приложит cookie к запросу тега `<audio>`,
так как это same-origin запрос, а `SameSite=Lax` это разрешает).

## Серверы, каналы, роли

Нужны для настройки анонимных сообщений — каждый параметр (канал, роли)
физически привязан к конкретному Discord-серверу, общей настройки на всего
бота быть не может.

| Метод | Путь                              | Ответ                                                    |
|-------|-------------------------------------|----------------------------------------------------------|
| GET   | `/api/guilds`                        | `[ { "id": string, "name": string } ]` — серверы, где установлен бот |
| GET   | `/api/guilds/{guild_id}/channels`    | `[ { "id": string, "name": string } ]` — текстовые каналы сервера |
| GET   | `/api/guilds/{guild_id}/roles`       | `[ { "id": string, "name": string } ]` — роли сервера (без managed-ролей интеграций и `@everyone`) |

## Анонимные сообщения (/anon)

Настройки per-guild — хранятся в SQLite (`anon_settings`), не в JSON.

| Метод | Путь                              | Тело / Ответ                                                                                     |
|-------|-------------------------------------|----------------------------------------------------------------------------------------------------|
| GET   | `/api/anon/settings/{guild_id}`      | `{ "guild_id", "enabled": bool, "channel_id": string\|null, "allowed_role_ids": string[], "cooldown_seconds": number }` |
| PUT   | `/api/anon/settings/{guild_id}`      | тело — `{ enabled, channel_id, allowed_role_ids, cooldown_seconds }`; ответ — обновлённый объект   |

Глобальный тумблер всего модуля (влияет сразу на все серверы) — поле
`modules.anonymous_messages` в `config.json`, редактируется через уже
существующий `GET/PUT /api/config` (см. раздел «Настройки» выше) — отдельная
страница «Модули» на фронтенде просто показывает эти поля как переключатели.

## Коды ошибок

Ошибки должны возвращаться в виде `{ "error": "человеко-читаемое сообщение" }`
с соответствующим HTTP-статусом (`400`, `401`, `404`, `409`, `500`).
Фронтенд показывает `error` из тела ответа, если оно есть.
